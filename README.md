# Browser Check-in / 网页签到工具集

在脚本猫中使用当前浏览器登录态，统一管理知遥 API、ECY Cloud、库库 AI 和 HiFiTi 音乐磁场的当天签到。浏览器启动时逐站检查当日成功记录，仅为尚未完成的网站打开标签页。提供站点开关、访问时签到、手动签到与状态提示；代码通过 GitHub 维护和订阅更新。

## 安装订阅

在安装了脚本猫的浏览器中打开：

**[安装网页签到工具集订阅](https://raw.githubusercontent.com/NameHitherto/browser-checkin/main/dist/checkin.user.sub.js)**

如果链接只显示文本，把这个 HTTPS 地址粘贴到脚本猫的订阅导入入口。首次订阅后，确认脚本列表里同时存在并启用了：

- `三站签到 · 页面执行器`
- `三站签到 · 定时与一键执行`

名称沿用旧版以保持升级身份；“定时与一键执行”现为启动时运行的后台脚本。也可以分别安装 [页面执行器](https://raw.githubusercontent.com/NameHitherto/browser-checkin/main/dist/worker.user.js) 和 [启动检查脚本](https://raw.githubusercontent.com/NameHitherto/browser-checkin/main/dist/scheduler.user.js)；这与合集订阅二选一即可。升级到 1.3.0 时需要同时更新这两个脚本。

1.3.0 新增的 HiFiTi 默认启用，可在站点设置中关闭；访问首页时自动签到，帖子页不会自动签到。脚本仍沿用“三站签到”的旧名称以保持升级身份。

从本地导入的 1.0.0 升级时，先停用旧版，安装订阅/新版后确认两个名称各只有一个启用的实例，避免重复执行。`name`、`namespace`、`storageName` 保持原值，旧状态可继续使用；新版增加的个人配置采用默认值。

## 使用与个人设置

1. 在同一个浏览器配置文件中，手动登录各目标网站。
2. 保持两个脚本启用。每次浏览器启动（或重新启用后台脚本）时，自动读取各网站的当天成功记录，仅为尚未完成的网站依次打开后台标签页进行签到，完成后按设置自动关闭标签页。
3. 点击 **站点与启动设置**，或在脚本猫列表中打开“页面执行器”的用户配置：可逐站启停，设置是否启动时检查、是否访问时执行、是否关闭成功页面以及是否通知。
4. 当自动签到失效或需要强制核验时，可在脚本猫菜单（包括后台脚本全局菜单）选择 **全部已启用网站：立即重新核验并签到**：脚本会绕过本地今日成功缓存，自动打开所有已启用注册站点并在官网重新核验真实签到状态（网页内触发时会交由后台脚本执行，关闭当前网页不会中断）。单站菜单 **本站：检查并签到** 同样强制核验当前页面；“打开本站签到页”可用于人工查看官网。

每个网站分别保存成功日期与确认状态，仅官网确认“签到成功”或“今日已签”后才记为完成。当天重启浏览器时，已成功的网站不会再次打开，失败的网站可重新尝试。登录失效、人工验证、错误和结果不明都不算成功，也不会覆盖已有成功记录；手动强制重新核验若发现实际未登录/失败，会清除误记的当日状态。

日期按本机时区的自然日计算，次日 `00:00` 旧记录自动失效，无需等满 24 小时。本工具已移除每分钟定时轮询功能：浏览器持续开启期间后台不运行定时任务；如需在新一天或补救时执行，可重启浏览器触发启动检查或直接点击“立即重新核验并签到”。

新版不再使用原先的固定时间调度与每分钟定时轮询；旧时间设置保留在本地但不参与调度。脚本名称、共享存储、站点开关和其余个人设置保持原有身份。原来的“启用定时签到”开关继续作为“启用浏览器启动时自动签到”使用。

禁用某站后，访问时签到、单站菜单、手动全站核验和启动检查都不再提交该站请求。禁用启动自动检查仅停止启动时打开网页，手动一键核验仍可使用。页面已开始发送的请求不能撤销。

默认已签到/成功的临时页面会关闭；需要登录、人工验证或结果不明的页面保留。用户设置可选择保留所有页面。登录失效时在官网重新登录，再运行；无需复制 Cookie/Token。库库工作台可通过“打开本站签到页”进入活动页。

浏览器退出、电脑关机或休眠期间无法执行；下次启动时只检查当天，不补签历史日期。若上次浏览器异常退出留下无心跳批次锁，启动检查会在约 6 秒确认无心跳后接管继续执行。

日常开销：移除定时执行后，后台脚本在完成启动检查后进入零定时器、零轮询的事件待命状态（仅响应全局菜单与网页手动核验指令），不主动读写扩展存储、不请求网络、不扫描页面、不输出日志。脚本只匹配注册表中的四个网站，不注入其他网站或子框架。仅实际签到或手动核验期间打开网站并短时等待结果，成功后按设置关闭临时页；需要人工处理的页面会保留。

## 支持与证据范围

| 网站 | 方式 | 成功判据 |
|---|---|---|
| 知遥 API | 同源 API；实时读取页面 `user_token` | 签到后查询 `today_checked_in` |
| ECY Cloud | 等待页面初始化，关闭官网提示弹窗后点击当天签到一次；官网处理会话与参数 | 官网签到区域明确更新为今日已签到 |
| 库库 AI | 点击当前官方活动签到按钮，由官网生成动态参数 | 官网按钮明确显示今日已签 |
| HiFiTi 音乐磁场 | 在首页按指定 XPath 点击官网签到入口一次 | 首页 `/` 或跳转 `/sg_sign.htm` 后 `/html/body/main/div/div/div[2]/div[1]/span/div[1]` 明确显示“已签” |

不抽奖、不补签、不购买、不执行对话任务。遇到验证码交给用户；活动截止、接口或页面变化可能需要更新适配器。

目前有 70 项离线行为场景、2 项后台零定时器空闲性能检查及 3 项构建/注册检查，涵盖启动单次触发、手动一键全站强制重新核验、弹窗顺序、单次点击、逐站状态、同日重启、停用和升级保留设置等。**未在用户的脚本猫实例中完成四站未签到到成功签到的真实账号验收。** CI 通过也不能证明真实网站当天签到成功。[接口与验证说明](docs/EVIDENCE.md) · [ECY 流程与验收映射](docs/ECY-FLOW.md)

## 维护

- 用户：在脚本猫配置中启停站点，设置检查更新间隔；不要直接改 `dist` 文件。
- 维护者：新增/删除站点或修复接口时提高版本、生成脚本、运行测试与一致性检查并自动发布（推送 `main` 与 `v*` 标签触发 GitHub Actions 自动创建 Release 并更新 `main/dist` 订阅地址）。[维护指南](docs/MAINTENANCE.md)
- 个人设置只在脚本猫本地存储，仓库和构建物不包含账号、Cookie、Token、订阅链接或真实运行记录。

Node.js 20 或更新版本，无第三方运行依赖：

```sh
npm run build
npm test
npm run check
```

结构：`src/registry.json` 是站点注册表；`src/sites/` 是独立适配器；`scripts/build.mjs` 统一生成 `dist/` 的执行器、定时脚本、更新元信息与订阅。

订阅机制与用户配置参考脚本猫的 [订阅文档](https://docs.scriptcat.org/docs/dev/subscribe/)、[用户配置](https://docs.scriptcat.org/docs/dev/config/) 和 [脚本元信息](https://docs.scriptcat.org/docs/dev/meta/)。
